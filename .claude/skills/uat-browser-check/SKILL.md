# 受け入れ条件のブラウザ確認（報告のみ）

ユーザーが挙げた受け入れ条件（`$ARGUMENTS` または依頼文の箇条書き）を、実際の画面で 1 行ずつ確かめる。**コードは直さない。** 満たさなかった条件は、そのまま報告する。

## 0. 準備

- Playwright のツールは deferred なので、`ToolSearch` で `select:mcp__playwright__browser_navigate,mcp__playwright__browser_snapshot,mcp__playwright__browser_take_screenshot,mcp__playwright__browser_evaluate,mcp__playwright__browser_click,mcp__playwright__browser_type,mcp__playwright__browser_run_code_unsafe,mcp__playwright__browser_close` のように先に読み込む。
- アプリが起きているか `curl -s -o /dev/null -w "%{http_code}" http://localhost/login` で確かめる（200 なら OK）。起きていなければ `./vendor/bin/sail up -d`。
- スクリーンショットの置き場（既定は `uat-shots/`、ユーザー指定があればそれ）を `mkdir -p` で作る。
- メモリに [[playwright-click-not-working]] / [[playwright-japanese-fonts]] があるので読む。スクショで日本語が □ なら `fc-list :lang=ja | wc -l` を見る。
- 確かめる前の**状態を DB で控える**: `./vendor/bin/sail artisan tinker --execute='...'` で件数や対象行を出す。確認で増減させたものを後で元に戻すためにも要る。出力が長いときは `tail` で切らず、必要な列だけ出す（切ると最初の行を見落とす）。
- 確認用データは開発 DB（Sail の MySQL）に入る。`testing` DB ではない。テスト用に作ったデータは、最後に自分で消す。
- ログイン済みかもしれない。`/login` を開いて `/posts` に飛ばされたら、ログイン済み。画面ヘッダの「名前（メール）」で誰かを確かめる。

## 1. 操作の方針

- **まず実クリックを試す。** 効いたら、そのまま実クリックで進める。効かなければ（submit が飛ばない・Tab で動かない）、`browser_evaluate` で `form.requestSubmit()` に切り替え、**報告に「実クリックではなくフォーム送信で代用した」と書く**。同じクリックを何度も繰り返さない。
- 操作の前に `browser_snapshot` で ref を取り直す（遷移のたびに接頭辞が変わる）。入力は `browser_type`（fill）。
- 送信が通ったかは、**画面と DB の両方**で見る。画面だけで「増えた」と書かない。
- ログイン・ログアウトが要るときは、ログアウトボタンを押し、`/login` で `browser_run_code_unsafe` を使って `input[name=email]` / `input[name=password]` を埋めて送る。練習用アカウントは CLAUDE.md を見る（`usera@example.com` / `userb@example.com`、パスワードは `password`）。

## 2. 条件の型ごとの確かめ方

- **「一覧・詳細が見える」**: 画面に遷移して、スナップショットで要素（本文・一覧・フォーム）が出ていることと、数を数える。リンクは実際に押して遷移する（URL 直打ちにしない）。
- **「入力して送ると増える」**: 送信前の件数 → 一意に分かる本文を入力 → 送信 → 画面の件数と新しい行 → DB の件数、の順。本文は「UAT確認用…」のように、後で見分けられるものにする。
- **「空だとエラーで増えない」**: 空のまま送信 → 入力欄の下のエラー文（CLAUDE.md の日本語メッセージどおりか）→ DB の件数が**変わらない**ことまで見る。ブラウザの `required` ではなくサーバー側のエラーであることも、再描画された画面で確かめる。
- **「自分のものは消せて、他人のものは消せない」**（認可）は、次の 4 つをそろえる。
  1. 自分のものの削除ボタンを押し、画面から消えることと DB から消えることを見る。
  2. 他人のものがある画面で、削除ボタンが**出ない**ことを `browser_evaluate` で数える（`article` ごとの `button` 数）。ポストの作者であっても、他人のリプライには出ない仕様。
  3. 画面を通さず、`fetch('/…/{id}', {method:'POST', body:{_method:'DELETE', _token}})` を `browser_evaluate` で送り、**403** が返ることと、DB に残っていることを見る。CSRF トークンは画面の `input[name=_token]` から取る。
  4. ログアウト → 別ユーザーでログインし、逆向き（相手のものが消せない）も同じ 2〜3 を行う。
- 「他人のデータ」を探すときは、事前に tinker で、行ごとの作者（`user->email`）を出す。見つからなければ、確認用に別ユーザーで作ってから確かめ、後で消す。

## 3. スクリーンショット

- 名前に**どの条件のものか**が分かる接頭辞を付ける。例: `1-post-detail-with-replies.png` / `2-reply-added.png` / `3-empty-reply-error.png` / `4a-own-reply-deleted.png` / `4b-others-reply-no-delete-button-userA.png`。同じ条件で複数あれば `a` `b` `c` を付け、**誰の画面か**も名前に入れる。
- `browser_take_screenshot` に `filename`（相対パスで `uat-shots/…`）と `fullPage: true` を渡す。
- **撮ったものは `Read` で 1 枚は目視する**（特にエラー表示のもの）。日本語が □ になっていないか、証拠として写っているかを確かめる。撮っただけで「証拠あり」と書かない。
- 状態が変わらない操作（403 を直接送るなど）は、画面に出ない。その条件の証拠は、スクショ（ボタンが無い画面）と、`browser_evaluate` の結果・DB の値を併記する。

## 4. 後片付け

- 確認用に作ったデータを消し、DB の件数が**確認前に戻った**ことを tinker で見る。
- 自動採番は戻らない。報告に一言書く。
- `.playwright-mcp/` と `uat-shots/` は git の未追跡として出る。**この時点では消さない**（人がスクショを見るまで証拠として残す）。削除は「6. 人の確認が終わったあとの削除」で行う。
- 実クリックが効かなかった・日付が違うなど、メモリの記述と違う結果が出たら、メモリを直す。

## 5. 報告の形

1 行 1 条件の表にする。列は **# / 確認項目 / 判定 / 判断した理由 / スクリーンショット**。

- 判定は 3 値: **満たす** / **満たさない** / **判定不可**。判定不可のときは、何が足りないか（他人のデータが無い・画面に出ない）を書く。
- 理由には、**見たもの**を書く（画面の文言・件数の前後・HTTP ステータス・DB の値）。「問題なさそう」だけにしない。
- 実クリックか、`requestSubmit()` による代用かを書く。代用なら「ボタンを押したときの挙動まで」は確かめていないと書く。
- 実行していない・見ていないことを、見たように書かない。
- 表のあとに、後片付け（消したもの・残ったもの・未追跡フォルダ）を短く書く。
- 満たさない条件があっても、コードを直さず、どこで・どう満たさなかったかを書く。
- 報告の最後に、「スクショを確認し終わったら知らせてください。`uat-shots/` と `.playwright-mcp/` を削除します」と一言添える。

## 6. 人の確認が終わったあとの削除

`uat-shots/`（証拠のスクショ）と `.playwright-mcp/`（Playwright MCP が作るスナップショット・コンソールログ）は、人がスクショを確認し終わったら用済みになる。そのときだけ両方を削除する。

- **勝手に消さない。** 削除するのは、ユーザーが「確認が終わった」「消していい」と言ったあと。報告を出した直後や、次の依頼が来ただけでは消さない。ユーザーが確認の途中で追加撮影や再確認を求めたら、消さずに続ける。
- **消すのはこの 2 つだけ**: プロジェクトルート直下の `uat-shots/`（ユーザーが別の置き場を指定していたら、その置き場）と `.playwright-mcp/`。他のフォルダや、`uat-shots/` の外のファイルには触れない。
- 手順:
  1. `browser_close` でブラウザを閉じる（開いたままだと `.playwright-mcp/` にまた書かれる）。
  2. Bash の作業ディレクトリがプロジェクトルートか確かめる（`.playwright-mcp/` の中に `cd` したままにしない）。**絶対パス**で指定する: `ls -la <ルート>/uat-shots <ルート>/.playwright-mcp` で中身を見て、見覚えのあるファイル（`*.png` / `page-*.yml` / `console-*.log`）だけか確かめる。
  3. 想定外のファイルがあれば、消さずにそれを報告して、どうするか聞く。
  4. 問題なければ `rm -r <ルート>/uat-shots <ルート>/.playwright-mcp` を実行する。
  5. `git status --short` で、2 つとも未追跡から消えたことを確かめる。
- 削除は元に戻せない（どちらも git 管理外）。報告には、消したフォルダ名とファイル数を書く。
- どちらかをコミットしておきたい、と言われたら、消さない。
