# post-app

投稿を一覧・編集・削除できる、小さな Laravel アプリです。Tutorial 13 から 15 まで、このアプリ 1 本を題材に設計・実装・仕組み化を進めます。

## できること

- ユーザー登録・ログイン・ログアウト
- 投稿の一覧表示（投稿者の名前とカテゴリつき）
- 投稿の編集（タイトル・カテゴリ・本文）と削除
- 自分の投稿だけを編集・削除（他人の投稿は編集・削除ボタンが出ず、URL を直接開くと 403 になります）

## フォルダについて

`answers/` は Tutorial 13 の答え合わせ用で、アプリのコードとは関係ありません。設計書の解答例が入っているだけなので、アプリの動きには影響しません。詳しくは `answers/README.md` を見てください。

自分で作る設計書は `docs/` に置きます（Tutorial 13 の中で作ります）。

## 使用技術

| 項目 | 内容 |
|:-----|:-----|
| フレームワーク | Laravel 10 |
| 言語 | PHP |
| データベース | MySQL |
| 実行環境 | Laravel Sail（Docker） |
| 認証 | Laravel Fortify |

PHP と MySQL のバージョンは Sail のコンテナが決めます。手元で確かめるときは `./vendor/bin/sail php -v` と `./vendor/bin/sail mysql --version` を実行してください。

## セットアップ

Docker Desktop（または Docker Engine）を起動してから実行してください。Windows の方は WSL（Ubuntu）のターミナルで実行します。

```bash
# パッケージをインストールする
docker run --rm \
    -u "$(id -u):$(id -g)" \
    -v "$(pwd):/var/www/html" \
    -w /var/www/html \
    laravelsail/php82-composer:latest \
    composer install

# 環境ファイルを作る
cp .env.example .env

# Sail を起動する
./vendor/bin/sail up -d

# アプリケーションキーを作る
./vendor/bin/sail artisan key:generate

# テーブルを作り、練習用データを入れる
./vendor/bin/sail artisan migrate --seed
```

ブラウザで `http://localhost` を開くと、トップページが表示されます。

初回起動時は `migrate` で「Connection refused」が出ることがあります。MySQL の起動が終わっていないだけなので、少し待ってからもう一度実行してください。

## 練習用のアカウント

`migrate --seed` で、カテゴリ 3 件（お知らせ・技術メモ・雑記）と、次の 2 人、それぞれの投稿 2 件（計 4 件）が入ります。

| メールアドレス | パスワード | 投稿 |
|:---------------|:-----------|:-----|
| `usera@example.com` | `password` | `/posts/1`・`/posts/2` |
| `userb@example.com` | `password` | `/posts/3`・`/posts/4` |

本物の値は入っていません。すべて練習用のダミーです。

## 設計のメモ

### リプライ

- **作らないと決めたもの**
  - リプライへのリプライ。ポストに対するフラットな返信だけにする
  - リプライの `title` と `category_id`。一言返すための機能なので、本文だけを持たせる
  - ポストの作者が他人のリプライを消す権限
  - 送信・削除したときの完了メッセージ（ポストの編集・削除も出していないため、それに揃えた）
- **選ばなかった作り方**
  - 一覧は新しい順ではなく古い順にした（タイムラインは新しい順だが、リプライは会話の流れを読ませるため）
  - 送信・削除のあとはタイムラインではなく、同じポストの詳細画面へ戻す
  - 親ポストが消えたときのリプライ削除は、`ReplyPolicy` を通さず外部キーの連動削除（`cascadeOnDelete`）に任せた
  - 詳細画面からタイムラインへ戻る専用のリンクは作らず、ヘッダーのアプリ名（`posts.index` へのリンク）を使う
- **知らずに変えると壊れる決めごと**
  - リプライを直接消せるのは書いた本人だけ（`ReplyPolicy::delete`）。ポストの作者でも他人のリプライは消せない。削除ボタンも `@can('delete', $reply)` で本人にしか出さない
  - `replies` の `user_id` と `post_id` は連動削除。外すと、ポストやユーザーを消したときにリプライが残る（またはエラーになる）
  - 本文は必須・140字以内で、`\r\n` を `\n` に揃えてから数える。エラーメッセージもポストの編集と同じ文言で、片方だけ変えると食い違う
  - タイムラインの本文・日時のリンクが、詳細画面への唯一の入口。タイムラインの編集・削除の動きは変えない前提で作っている
- **設計書のありか**: [`docs/reply.md`](docs/reply.md)、Issue #1

### ポストの新規投稿

- **作らないと決めたもの**
  - 新しいテーブル・列・マイグレーション。`posts` に1行足すだけにする
  - `PostPolicy` の変更。ログインしていれば誰でも書けるので、`auth` ミドルウェア内にルートを置くだけにした
  - 新規投稿専用の画面ファイル。編集画面（`posts/edit.blade.php`）と兼用する
  - 完了メッセージ
  - タイトル・トピックのエラーの日本語化（する場合は別 Issue で、編集画面と同時に行う）
- **選ばなかった作り方**
  - 送信ボタンは、新規投稿でも編集と同じ「更新」にした。名前を分けたくなったら、見出しと同様に新規だけ「投稿」にする
  - 「ポストする」ボタンは、タイムラインの固定ヘッダー（`.chrome`）の中に置いた。ヘッダーごと常に表示されるので、JavaScript などの新しい仕組みは要らない
  - `user_id` はフォームから受け取らず、ログイン中のユーザーの ID をサーバー側で入れる
- **知らずに変えると壊れる決めごと**
  - `GET /posts/create` は `GET /posts/{post}` より前に定義する。後ろだと `create` がポストの ID と解釈されて 404 になる
  - 作成画面と編集画面は部品を共通化している。違いは、見出し・入力欄の初期値・トピック先頭の「選択してください」・送信先の4点だけ。共通部分を変えると、編集画面の表示・ボタン名・送信先・エラー表示が変わる
  - 本文の入力チェックは `ValidatesContent::validateContent` を、ポストの編集・リプライと共有している
  - タイトル・トピックのエラーは、編集画面と同じ Laravel 標準の英語のまま。片方だけ日本語化しない
  - トピックの「選択してください」は値が空で、選ばずに送るとエラーになる。この仕組みで必須を保っている
  - 「ポストする」ボタンを固定ヘッダーの外へ出すと、スクロールで消える
- **設計書のありか**: [`docs/post-create.md`](docs/post-create.md)、Issue #3
